# GSP1348 - Get Started with Vibe Coding and Antigravity CLI

You paste shell blocks in one terminal and prompts into the Antigravity CLI (agy) in another. Nothing to edit in this lab: every value is detected.

## Known lab traps/bugs (read first)

1. Every checkpoint only passes after a summary file is in the grading bucket (your project ID plus -grading). The checker looks for the file by name. The lab text shows the bucket as "gs://-grading/" with the project missing; Setup below builds the right name.
2. The lab hardcodes /home/student/event-talks-app in the MCP config and in the prompts. Your home folder is not /home/student (it is /home/student_xx_xxxx). This tutorial writes your real path into the config, and the prompts say ~/event-talks-app.
3. The lab says to click a "Proceed / Run" button. In the CLI there is no button: press Enter on "Yes, allow once" (this lab also allows "Yes, allow always", which saves many rounds).
4. Here the AI only writes each summary file. You upload it yourself with a paste block, so a failed AI upload can never cost you the checkpoint.
5. The Task 5 config overwrites the agy settings file. If agy asks you to sign in again afterwards, just repeat the sign-in.
6. The checker lags: wait 30-60 seconds and click again.

Use two terminals. Click Open Editor, then Terminal > New Terminal, then the + icon for a second one. Terminal A runs agy. Terminal B is for the paste blocks.

## Setup (Terminal B)

```bash
gcloud config get-value project > ~/project
printf 'gs://%s-grading/\n' "`cat ~/project`" > ~/bucket
mkdir -p ~/antigravity-projects ~/.gemini ~/.antigravity
head ~/project ~/bucket
gcloud storage ls `cat ~/bucket` && echo bucket OK
```

You should see your project ID, a bucket like gs://YOUR-PROJECT-grading/ and bucket OK. Keep the project ID visible: the sign-in asks for it.

## Task 5. Git MCP server

An MCP server gives agy new tools. Here it is a Git server started with npx, pointed at one repository.

Terminal B - create the repository:

```bash
mkdir -p ~/event-talks-app
cd ~/event-talks-app
git init
git config user.name "Student"
git config user.email "student@qwiklabs.net"
echo "# Event Talks App" > README.md
git add README.md
git commit -m "Initial commit"
git log --oneline
```

You should see one commit: Initial commit

Terminal B - write the MCP config with your real path:

```bash
cat > ~/.antigravity/settings.json <<'EOF'
{
  "mcpServers": {
    "git": {
      "command": "npx",
      "args": [
        "-y",
        "git-mcp-server",
        "REPO_PATH"
      ],
      "trust": true
    }
  }
}
EOF
sed -i "s|REPO_PATH|`cd ~/event-talks-app && pwd`|" ~/.antigravity/settings.json
cp ~/.antigravity/settings.json ~/.gemini/settings.json
python3 -m json.tool ~/.antigravity/settings.json
```

You should see the JSON with a path like /home/student_xx_xxxx/event-talks-app (not /home/student and not REPO_PATH).

Terminal A - launch from the repository folder:

```bash
export NODE_NO_WARNINGS=1 GOOGLE_CLOUD_LOCATION=global
cd ~/event-talks-app
agy
```

If asked whether you trust the folder, choose Yes. In agy, type:

```text
/mcp
```

You should see git with a list of tools (status, add, commit and more). The first start downloads the server, so if it is not listed yet, press ESC, wait 20 seconds and type /mcp again. Press ESC to leave the list.

Paste:

```text
Check the git status of the repository at ~/event-talks-app using the git MCP server tools.
```

You should see a git MCP tool call (not a shell command) reporting the branch and a clean tree.

Summary prompt:

```text
Please write a summary_task3.md file in the current directory that lists:
- The status of the Git repository at ~/event-talks-app inspected via the Git MCP server
- The branch name and tracked files in the repository

Only write the file. I will upload it myself.
```

Terminal B - upload:

```bash
gcloud storage cp `find ~ -maxdepth 3 -name summary_task3.md | head -1` `cat ~/bucket`
gcloud storage ls `cat ~/bucket`
```

You should see three summary files.

Check my progress: Verify local repository using Git MCP tools

Back in agy, paste:

```text
Create a new file named talks.json in ~/event-talks-app with sample event schedule data, add it to git, and commit the changes with the message "Add talks schedule".
```

Terminal B - confirm the commit really happened:

You should see the commit Add talks schedule on top and the file talks.json. If the commit is missing, tell agy what you saw and ask it to finish.

## Task 6. Vibe coding a website (no checkpoint)

In agy, paste:

```text
Generate a website for a 1-day event filled with technical talks. There are going to be 6 talks in a single track of 1 hour each. Each talk has the following information: title, 1 or maximum of 2 speakers, category (1 or maximum of 3 keywords), duration and a description. The website has a single page where users can see the schedule for the entire day with the timings. There will be one lunch break of an hour and the event starts at 10:00 AM. Keep a 10 minute transition between talks. I would like to use Node.js on the server side and standard HTML, JavaScript, and CSS on the front-end. The users should be able to search the talks based on category.

I would like you to proceed in the following way:

1. Plan out how you would design and code this application.
2. Ask me for any clarifications along the way.
3. Once I am fine with it, do generate the code, and compile the website into a single, serverless HTML file.
4. Provide me with instructions to run and test the website on port 8080 (serve the index.html file to me using a simple Python server on port 8080 so I can preview it locally via Cloud Shell Web Preview).
```

When it asks for clarifications or how to proceed, paste:

```text
Create the website using placeholder data and proceed as per your plan suggestions.
```

Notice the prompt asks for a plan first and invites questions. That is the vibe coding habit to copy: agree on the plan before any code is written.

To preview, serve the page from Terminal B so agy stays free:

```bash
cd "`find ~ -maxdepth 4 -name index.html -not -path '*/node_modules/*' | head -1 | xargs dirname`"
ls index.html
python3 -m http.server 8080
```

You should see index.html, then "Serving HTTP on 0.0.0.0 port 8080". Click Web Preview (top right of Cloud Shell) > Preview on port 8080. Stop the server with CTRL+C.

Other fixes: /model switches model on a quota or capacity error. ESC stops the AI if it loops; then repeat or sharpen your instruction.
